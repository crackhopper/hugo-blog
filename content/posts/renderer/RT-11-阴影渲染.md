## Shadow Map

- 从光源角度，渲染深度，得到 shadow map
- 从相机角度，查询 shadow map，来计算颜色。

## Problem1：自遮挡 (Self Occlusion/Shadow Acne)
![[RT-11-阴影渲染-problem1自遮挡-self-occlusionshadow-acne-01.png|354x332]]


原因：
![[RT-11-阴影渲染-problem1自遮挡-self-occlusionshadow-acne-02.png|606]]

- 由于 shadow map 记录的深度不连续，因此会将一个平面上大部分的区间都固定为一个值，从而导致了，shadow map 还原回来，不是一个真正的平面。（在grazing angle下，问题更多）

**解决方案：** Bias
- 判断某个pixel的SM深度的时候，要求小于的判断，要额外多小于一定的量。即，要求遮挡要足够远。（有个Bias）
- 此外，这个Bias可以根据光源角度动态调节。（因为grazing angle下问题更严重，因此可以调大）
- **新的问题**：
	- 一些薄片物体，会有白边（因为遮挡物恰好在Bias内）：
	- Detached shadow 的问题：两个面相交的位置，有部分的影子断了。

## P1/P2-SOL1: Second-depth shadow mapping 
**做法： 保存两个深度： 最浅+次浅。比较的时候用中间值。**

![[RT-11-阴影渲染-p1p2-sol1-second-depth-shadow-mapping-01.png]]



解决什么问题？
- **免去手动调节 Bias 的痛苦（Auto-biasing）：** 对于一个闭合的实体（比如一个角色或一个正方体），$d_1$ 是朝向光源的正面，$d_2$ 是背向光源的背面。中间值 $d_{\text{mid}}$ 完美的位于物体的**内部**。 当渲染正面时，正面像素的当前深度是 $d_1$。我们用 $d_1$ 去和 $d_{\text{mid}}$ 比较：因为 $d_1 < d_{\text{mid}}$，所以正面绝对不会被判定为在阴影中！ **这就相当于自动生成了一个大小完美的 Bias（大小等于物体厚度的一半），从根本上避免了表面因为精度问题产生的自遮挡。**
	- 如果是上面的ground上的问题，把ground调整厚，那么每个点的阴影判断都在ground盒子的内部。但如果ground很薄也会有问题。

- **缓解了悬空阴影（Peter Panning）：** 因为这个“自动 Bias”是动态适应物体厚度的，它不像传统的大 Bias 会把阴影粗暴地往后推，从而在一定程度上让阴影和物体接触得更紧密。
	- 物体如果厚一些，确实也不会有悬空阴影问题。但如果物体薄，那么还是有概率会被其他物体的自适应bias影响，从而导致仍然产生悬空问题。

**实际用的比较少，因为有以下缺陷**
- 假设所有物体都是“厚”的（闭合流形）：也叫做 water-tight
- 复杂的自遮挡依然存在（重叠结构）
	- 如果一个复杂模型自己折叠自己（比如衣服的褶皱、高模角色的腋下、多层树叶），次浅深度 $d_2$ 捕捉到的可能已经是另一个碎片的正面了。
	- 如果 $d_1$ 和 $d_2$ 靠得极近（比如两层紧贴的衣服布料），$d_{\text{mid}}$ 留给表面的安全空间就会极小。
	- **结果：** 只要有浮点精度误差，自遮挡依然会发生。你还是得加一个微小的斜率 Bias（Slope Bias）。
- 严重的漏光（Peter Panning）转移了
	- 在双层阴影中，如果一个薄片悬空在地面上，中间值 $d_{\text{mid}}$ 可能会被拉得很大，导致原本应该有阴影的地方判定失败，产生比传统 Shadow Map 更诡异的**漏光现象**。

**最后：记录两个数值，速度慢；需要更多判断** 

**RTR does not trust in COMPLEXITY**

## PCF (Percentage Closer Filter)
最早用来做抗锯齿。不是为了做阴影的。用在阴影里，叫做PCSS。（对阴影查询，做了一个filter)

具体做法：对于一个点，查询的时候，查询多个点。然后用查询到的多个值做平均，得到percentage的遮挡（可以加权；但分母也要归一化）。

![[RT-11-阴影渲染-pcf-percentage-closer-filter-01.png]]

阴影锯齿会被弱化。

取filter大小：
- Small：更加锐利
- Large：更加软
利用这个特性，得到 PCSS

## PCSS (Percentage Closer Soft Shadows)
![[RT-11-阴影渲染-pcss-percentage-closer-soft-shadows-01.png]]
- 阴影的soft，需要和产生阴影本体的距离。
	- 如果距离越近，那么filter越小。
	- 如果距离越远，那么filter越大。


更具体的做法（概念上）：

![[RT-11-阴影渲染-pcss-percentage-closer-soft-shadows-02.png]]

- d_blocker ： 遮挡物距离光源
- d_receiver :  阴影查询点，距离光源
- w_light : 光源大小
- 最终 w_penumbra ：阴影软的程度，越软，filter越大。

**实现细节** （两次对SM进行区域/多点查询；）
1. 搜索 blocker 的深度。（忽略所有不是blocker的；在SM上也是取一个区域的blocker的depth，过滤掉非blocker）
	1. 这里区域怎么找？可以默认5x5之类的。
	2. 直接从查询点向光源边缘发出连线。获取到具体的查询大小。（参考下一节）
2. penumbra estimation：用上面的公式，得到阴影软的程度：
	1. 如何计算filterSize？通常要除以光源的视锥体宽度（$W_{\text{light\_frustum}}$，即光源在对应距离上的照射范围宽度） 即等于 $w_{penumbra}/W_{lightfrustum}$ 。点光源可以理解为除以光源的具体距离。
3. pcf：根据软的程度，决定filter的面积大小。多个查询后，平均。

### 光源视锥体宽度怎么算
这个值是，receiver上的位置上，光源照射的面积。因此，距离光源越远，越大。故filter size，最后再除以这个调整一下。

我们做这一步的目的，是为了**把“世界空间下的米/物理单位”转换成“Shadow Map 上的 UV 比例（0.0 到 1.0）”**。

想象一下：
- 如果一个点光源的照射范围（视锥体）在某个距离上宽度是 **10米**。
- 你算出来的半影（Penumbra）宽度是 **1米**。
- 那么这个半影在 Shadow Map 上占用的 UV 比例就是 $\frac{1}{10} = 0.1$。
- 如果你的 Shadow Map 尺寸是 1024 像素，那你的 Filter Size 就是 $1024 \times 0.1 = 102.4$ 个像素。


### 全向点光源（Omni-directional / Point Light）

为了捕捉 360° 的阴影，现代引擎（如 Unreal、Unity）普遍采用 **Cube Shadow Map（立方体阴影贴图）**。

**它是如何变成“有视锥”的？**

引擎会将周围的空间切成 6 个正方形的面（前、后、左、右、上、下），然后**架设 6 个虚拟的正交或透视摄像机**去渲染 6 张 Shadow Map。

- **视角（FOV）：** 为了完美拼成一个立方体，这 6 个摄像机的视角（Field of View）被固定设为严格的 **90°**。
    
- **它的视锥体宽度是什么？** 此时，每个面的渲染就是一个标准的透视投影。我们在计算当前像素（Receiver）时，只需要知道它落在了立方体的哪一个面上。在这个特定的面上，**$W_{\text{light\_frustum}}$ 就是该方向上，在接收面深度（$d_{\text{receiver}}$）处，这个 90° 视锥体的物理截面宽度**。
    

利用简单的三角函数（由于 $\tan(45^\circ) = 1$），在距离点光源 $d$ 处的视锥体单侧宽度就是 $d$，所以整个视锥体的物理宽度就是：

$$W_{\text{light\_frustum}} = 2 \cdot d_{\text{receiver}}$$

代入你之前的公式，你会发现 $d_{\text{receiver}}$ 甚至可以在推导中被约掉，计算会变得非常优雅。

### 聚光灯（Spot Light）

在很多游戏里，为了省显存，策划口中的“点光源”（比如一盏吊灯、一个手电筒）在底层其实是被当作聚光灯（Spot Light）实现的。

聚光灯是有明确边界的。

- **它的视锥体宽度是什么？** 它有一个明确的圆锥总开角 $\theta$（Cone Angle）。那么在接收点深度 $d_{\text{receiver}}$ 处，这个聚光灯照射范围的物理直径（宽度）就是：
    

$$W_{\text{light\_frustum}} = 2 \cdot d_{\text{receiver}} \cdot \tan\left(\frac{\theta}{2}\right)$$

这个宽度是有限的、明确的，直接代入 PCSS 公式即可。

### 工业界常用的经验公式（TRICK 与优化）
在实际的游戏开发（如 Unreal Engine, Unity 或自定义引擎）中，如果直接死板地套用上面的理论公式，会遇到一系列恶心的**画面瑕疵（Artifacts）**和**性能灾难**。因此，图形程序员通常会使用经验公式进行修正：

**经验修正1：** 必须强制设定一个最大采样半径。

如果 $d_{\text{blocker}}$ 极小（比如遮挡物无限贴近光源），或者 $d_{\text{receiver}}$ 极大，算出来的 $w_{\text{penumbra}}$ 会趋于无穷大。这时候 PCF 的采样半径会大到吃满整张 Shadow Map，显卡会直接卡死。


$$\text{Filter Size}_{\text{final}} = \min(\text{Filter Size}_{\text{calculated}}, \text{Max Filter Radius})$$

**经验修正2**: 平滑过渡的非线性映射（Smoothstep）

理论公式是纯线性的。但在视觉上，阴影从“极锐利”过渡到“极软”如果太线性，会显得不够自然，或者在特定距离出现突变。

```glsl
float penumbra_factor = smoothstep(0.0, 1.0, norm_penumbra * u_LightRadiusScale);
```

**经验修正3**：常用采样器（如 Poisson Disk）的对齐

我们一般不是动态改变 `for` 循环的次数（因为 Shader 中动态循环非常低效），而是**固定采样次数（例如 16 次），通过改变采样点的间距（Stride/Radius）来改变 Filter Size**。
```
// 确定了 filter_size_uv 后，遍历固定的泊松圆盘采样点
for (int i = 0; i < 16; i++) {
    // poissonDisk[i] 是一个半径为 1.0 的圆盘内的随机偏移量
    float2 sampleUV = receiverUV + poissonDisk[i] * filter_size_uv;
    float shadowDepth = texture(shadowMap, sampleUV).r;
    // ... 进行深度比较 ...
}
```

## VSSM(Variance Soft Shadow Mapping)

### pcf 优化
主要那个 $\chi$ 函数存在，导致我们没办法在SM上提前做filter。思考那个求和，实际上是等于数1的个数，也等价于计算自己在一系列阴影值（1）后面的排名（假设自己是0.5）。所以是一个分布求分位数的问题。可以假设分布，然后再用平均，从而快速求解排名。（这样前面的平均就是滤波的结果，方差也可以预计算出来）

**hint:求排名的问题，考虑用分位数+分布，可以快速求解**

![[RT-11-阴影渲染-pcf-优化-01.png]]

引入分布的思维，那么就可以用mipmap进行区域查询了。一个点直接查询一个区域。

如何计算排名？拿到自己的值，反查分布的CDF

![[RT-11-阴影渲染-pcf-优化-02.png]]


VSSM，在求解这里，不查表，直接用切比雪夫不等式。（相当于求分位数可以考虑切比雪夫不等式作为逼近）
- 因此可以直接求解p分位数为 $p=1-\frac{\sigma^2}{\sigma^2+(x-\mu)^2}$ 。用这个值就可以得到p分位数的估计（下界）了。（其中x是当前点查询得到的深度；mu是区域均匀深度；sigma是区域均匀深度的方差）
	- 如果假定了正态分布，可以有更加简单的修正估计（这块是显然的；注意这个公式在 x=\mu 附近会有很大的偏差）

### block search 优化
遮挡物深度，因此本身需要比较后，再进行平均。

![[RT-11-阴影渲染-block-search-优化-01.png]]

要求解上面变量：显然有关系

$$
\frac{N_1}{N}z_{unocc}+\frac{N_2}{N}z_{occ}=z_{avg}
$$
我们要求解 $z_{occ}$ 。这里面有很多已知的（z_avg），有分位数可以用切比雪夫不等式估计（N1/N，N2/N）。最后还有一个不知道的 z_unocc ，假设值和当前深度值一样（实际上把值变小了，从而遮挡物实际平均深度可能变大了，查询影子范围相对变小）。

![[RT-11-阴影渲染-block-search-优化-02.png]]
